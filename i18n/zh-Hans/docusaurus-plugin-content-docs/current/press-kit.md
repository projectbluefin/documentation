# Bluefin 术语

项目的名称是 `Project Bluefin`，但通常简称为 `Bluefin`。Bluefin 发布在 [projectbluefin](https://github.com/projectbluefin) GitHub 组织下，使用 [Universal Blue](https://universal-blue.org) 的共享基础设施构建。Universal Blue 是一个社区伞形组织，还托管了 [Bazzite](https://bazzite.gg)、[Aurora](https://getaurora.dev) 和 [uCore](https://github.com/ublue-os/ucore)。

## 正确用法

- `Bluefin` - 用于指代项目以及/或操作系统
- `Bluefin DX` - 开启开发者模式的 Bluefin，在讨论开发者专属功能时相关

## 错误用法

- `BluefinOS` `Bluefin OS` 或 `Bluefin Linux` - 或对名称的任何其他附加，它就是 `Bluefin`
- `Fedora Bluefin` - 这暗示了 Fedora 与 Bluefin 之间的正式关系。有关 Fedora 与 Universal Blue 之间关系的更多信息，请查看[mission document](https://universal-blue.org/mission.html)
- `Atomic` 或其任何变体 - 这是 Fedora 的品牌名称，与 Bluefin 无关
  - 把两者都称为 Atomic 会削弱 Fedora 的品牌，因此用一组集体的称呼，比如 cloud-native operating systems，或者直接说 bootc images。或者说 bootable containers 也行，别想太复杂。bootc 是我们都依赖的技术，我们应该确保它在这类 Linux 中成为 #1 品牌。
  - 称它们为"atomics"完全不合适，除非你是 Paul Atreides
- `Universal Blue Bluefin` 或 `uBlue Bluefin` - 建议改为"Bluefin is built with Universal Blue"或"Bluefin is a Universal Blue image"。
- "Immutable Distribution" - Bluefin 是一个操作系统，它既不可变也不是发行版，它是一个由多个发行版集合而成的自定义镜像：Flathub、Homebrew 和 Fedora
  - 更好的说法是"a bootc image"、"a container image"，或者直接说"Bluefin"

# Universal Blue 术语

## 正确用法

- `Universal Blue` - 用于指代 Universal Blue 项目、GitHub 组织，或维护者的集合

## 错误用法

- `uBlue`、`UBlue`、`ublue-os`，或该词的任何缩写

`ublue-os` 用作操作系统中 URL 或路径的便捷别名，例如 `/usr/share/ublue-os`。

此外，在与终端用户沟通时，我们在提及该项目时要重复使用 Universal 这个词。对终端用户而言它是隐形的一层，这样焦点就能放在为所有人提供通用解决方案上。
