:::info[使命声明]

通过与云原生生态系统的整合来加速操作系统开发，为新开源贡献者提供入门通道。

:::

## 对生态系统的承诺

- 通过彻底摆脱传统的发行版模式，专注于以下领域来改善上游体验：
  - Flathub
  - Homebrew
  - 一个基础操作系统镜像
- 对镜像采取"无发行版（distroless）" Approach，项目应当是隐形的
- 通过有意限定范围来确保用户理解支持 Flathub 和 Homebrew 的重要性，从而积极鼓励上游贡献。
- 通过提供培训机会、导师计划和通过各种开源组织提供的多种贡献机会，积极吸纳新的贡献者进入开源世界。从 CNCF/Linux 基金会起步，并希望扩展到更多！
  - 积极倡导 Apache Buildstream、bootc、podman、kubernetes 等天生与发行版无关的工具。

## 社区与项目

- 努力成为一个管理良好的开源项目。
- 采用符合众人预期的去中心化治理：
- 项目应当能够通过典型 OSPO 在做尽职调查时使用的多数开源项目健康检查。团队尚未达到，但这是一个可以实现的目标。
  - 项目资源设计为可共享且去中心化，不存在类似 BDFL 的结构。
- 目标是加入一个能确保项目长期生命力的基金会或合作社。
- 确保达成透明度目标，长期信任是一个目标，因此必须建立相应流程来避免"巴士系数"风险。
- 构建结构化且多元化的社区：
- 明确的社区价值观与行为准则。

## 项目非目标

- 项目采用极简 Approach 来服务当前尚未使用 Linux 的人群。项目面向 96% 的用户，而非那 4%：
- 聚焦安装的长期可持续性
- 计算机生命的一小部分存在于第 0-3 天，项目有意识地投资于"这套安装应当贯穿硬件整个生命周期"的理念
- 项目会非常果断地界定范围外的事项。没有无缘无故的额外工作——作为 SRE/云原生的人，团队会拥抱懒惰、自动化一切，而不是编写自定义安装器去分割用户的磁盘，没时间搞那些
- 如果团队必须做某件事，那是因为别无选择；而即便必须做，团队也不会为此高兴。
- 项目大体上功能完备，不再做重大改动。算不上"维护模式"，但也不显著增加代码。团队在前期就大量说"不"，以保持项目的精简。
- 目标是给人们他们想要的东西，聚焦可持续性与维护，更像"我那位精通 Linux 的朋友帮我搭好了这套系统"，而不是一个分支或衍生版本。
- 团队成员拥有数十年的 Linux 发行版经验，发行版很难做，所以团队并不是在做一个"Linux 发行版"。
