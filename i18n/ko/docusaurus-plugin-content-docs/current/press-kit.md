# Bluefin 용법

프로젝트의 이름은 `Project Bluefin`이지만 보통 `Bluefin`으로 줄여 부릅니다. Bluefin은 [projectbluefin](https://github.com/projectbluefin) GitHub 조직 아래에 게시되며 [Universal Blue](https://universal-blue.org)에서 공유 인프라를 사용하여 구축됩니다. Universal Blue는 또한 [Bazzite](https://bazzite.gg), [Aurora](https://getaurora.dev), 그리고 [uCore](https://github.com/ublue-os/ucore)를 호스트하는 커뮤니티 우산입니다.

## 적절한 사용

- `Bluefin` - 프로젝트 및/또는 운영체제를 지칭하는 데 사용
- `Bluefin DX` - 개발자 모드가 켜진 Bluefin, 개발자 전용 기능을 논의할 때 관련성 있음

## 부적절한 사용

- `BluefinOS` `Bluefin OS` 또는 `Bluefin Linux` - 또는 이름에 대한 다른 추가, 그냥 `Bluefin`입니다
- `Fedora Bluefin` - 이는 Fedora와 Bluefin 간의 형식적 관계를 시사합니다. Fedora와 Universal Blue 간의 관계에 대한 더 많은 정보는 [mission document](https://universal-blue.org/mission.html)를 확인하세요
- `Atomic` 또는 그 변형 - 이는 Fedora 브랜드 이름이고 Bluefin과 관련이 없습니다
  - 그들을 둘 다 Atomic으로 부르는 것은 Fedora의 브랜드를 약화시키므로, 그룹으로 그들을 짉하이인 방법은 "cloud-native operating systems" 또는 그냥 "bootc images"입니다. 또는 그냥 "bootable containers", 너무 깊게 생각하지 마세요. bootc는 우리가 모두 의존하는 기술이고 부팅 가능한 컨테이너 스타일에서 이것이 #1 브랜드가 되도록 보장해야 합니다.
  - 그들을 "atomics"로 부르는 것은 당신이 Paul Atreides가 아닌 한 완전히 부적절합니다
- `Universal Blue Bluefin` 또는 `uBlue Bluefin` - 대신 "Bluefin is built with Universal Blue" 또는 "Bluefin is a Universal Blue image"가 권장됩니다.
- "Immutable Distribution" - Bluefin은 운영체제이며, immutable도 아니고 distribution도 아닙니다, 그것은 일련의 distribution의 집합인 맞춤 이미지입니다: Flathub, Homebrew, 그리고 Fedora
  - 더 좋은 예시는 "a bootc image", "a container image", 또는 그냥 "Bluefin"입니다

# Universal Blue 용법

## 적절한 사용

- `Universal Blue` - Universal Blue Project, GitHub 조직, 또는 유지보수자들의 집합을 지칭하는 데 사용

## 부적절한 사용

- `uBlue`, `UBlue`, `ublue-os`, 또는 용어의 축약

`ublue-os`는 운영체제에서 `/usr/share/ublue-os`와 같은 URL 또는 경로에서 편의용 슬로 사용됩니다.

또한 최종 사용자에게 전달할 때, 우리는 프로젝트를 언급할 때 Universal이라는 단어가 반복되기를 원합니다. 최종 사용자에게 보이지 않는 레이어이므로 초점을 모든 이를 위한 Universal 솔루션으로 옮길 수 있습니다.
