## Methodology, Privacy & Opt-Out

### Counting Methodology

Bluefin and Bluefin Utah use `countme.projectbluefin.io`. Classic is
`ublue-os/bluefin`, counted by `ublue-os/countme`.

All Bluefins adds Bluefin, Bluefin Utah, and Classic on each date. Classic uses the
recorded Bluefin badge history from `ublue-os/countme`; its last published weekly
reading is used until the next publication. Bluefin and Utah use their own daily
counts. Missing daily counts leave gaps. The badge values are rounded, so the
combined chart is an estimate, not a deduplicated device inventory.

### First-party Countme Service & Privacy Guarantees

Project Bluefin Dakota and Utah images send a daily active-system ping from the
`projectbluefin-countme` systemd timer to `https://countme.projectbluefin.io/v1/ping`.
Other images do not send it.

- **What is sent:** a single string, `<image-name>/<image-flavor>:<stream>`, where the stream
  is the booted image's tag (`stable`, `testing`, or `unknown`). Nothing else: no install age,
  architecture, machine ID, username, or persistent identifier.
- **How often:** at most once per day per system, and never from a live ISO, installer, or
  container.
- **What is stored:** one counter per UTC day and image. No per-system rows and no IP addresses.
  A day's count is the number of systems active that day, not distinct devices over time.

### Opt-Out Instructions

To stop Project Bluefin countme reporting now and across reboots, mask its systemd timer:

```bash
sudo systemctl mask --now projectbluefin-countme.timer
```

A mask of the previous `bluefin-countme.timer` or `bluefin-countme.service` units, and the
`/etc/projectbluefin/countme/disabled` opt-out file, still stop reporting.

To disable upstream Fedora countme:

- [Fedora countme documentation](https://coreos.github.io/rpm-ostree/countme/)

To disable Homebrew analytics:

```bash
brew analytics off
```

See the [Homebrew analytics documentation](https://docs.brew.sh/Analytics) for additional details.

### Contributor Metrics Methodology

Contributor analytics adopt a CNCF DevStats and LFX-derived methodology:

- **4 summary metrics and 3 trend charts:** Tracking monthly active human contributors, first-time contributors, pull request merge rate, and median turnaround time alongside historical trends for contributor cohorts, activity breakdowns, and PR velocity.
- **Public GitHub dataset with automated bot and AI agent filtering:** Metrics are derived from public GitHub activity while strictly filtering automated bots, dependency managers, and autonomous AI agents to ensure counts represent real human open-source participation.
- **Activity Streams on Tier-1 repositories:** Activity streams track the 9 tier-1 repositories on a shared domain to provide clear visibility into development velocity across code and builds, code reviews, issues, and documentation.
- **Community forum discussions:** Community discussions are hosted at [ublue-os/bluefin](https://github.com/ublue-os/bluefin/discussions).

For real-time development and organizational velocity metrics across all 15 factory repositories, see the [Factory metrics view](/factory/metrics).

Upstream repository metrics for `projectbluefin/bluefin` are also tracked on [Linux Foundation Insights](https://insights.linuxfoundation.org/project/ublue-os-bluefin).
